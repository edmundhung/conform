# shadcn/ui with Base UI

[shadcn/ui](https://ui.shadcn.com/) provides composable components that can be generated with [Base UI](https://base-ui.com/) primitives instead of Radix UI.

This Vite React project demonstrates how to use the Base UI variant of shadcn/ui with Conform, Tailwind CSS 4, and Zod 4 validation through `@conform-to/zod/v4/future`. It is the direct counterpart to the Radix-based [`shadcn-ui`](../shadcn-ui) example.

For the lower-level integration with Base UI primitives and Base UI's own Field composition, see the [`base-ui`](../base-ui) example. This example focuses on the additional component layer generated by shadcn/ui, including its Field, InputGroup, DatePicker, and InputOTP composition.

## Integration

When a generated shadcn component renders a normal `<input>`, `<select>`, or `<textarea>`, the example passes Conform's field props directly to it. The metadata provides the control, description, and error IDs consumed by shadcn's Field composition.

Compound controls use [`useControl`](../../docs/api/react/future/useControl.md) with a [`BaseControl`](../../docs/api/react/future/BaseControl.md). The base control is the single named form control, while the visible component handles interaction and remains unnamed to avoid duplicate `FormData` entries. The adapters translate Base UI's event and value shapes, forward changes and blur to the base control, and delegate invalid-submission focus to the interactive element.

Because the visible state follows the base control, initial and updated defaults, Conform reset intents, validation, and serialization stay synchronized without remounting the form. The interests combobox uses a multiple `BaseControl`, producing one `FormData` entry per selected value.

| Pattern | Components | Form integration |
| --- | --- | --- |
| Native form control | Input, Textarea, NativeSelect | The interactive element owns the name and serialization |
| Unnamed compound control | Checkbox, RadioGroup, Select, Combobox, Slider, Switch, DatePicker, InputOTP | The generated component handles interaction and accessible focus |
| `useControl` with `BaseControl` | All compound controls above | A hidden input or checkbox owns scalar and boolean values |
| Array `BaseControl` | MultiCombobox | A hidden multiple select serializes repeated values |

Conform remains the source of validation and form state, while shadcn/ui supplies field layout and styled interaction. The application keeps its native `<form {...form.props}>`. See [Integrating with UI Libraries](../../docs/integration/ui-libraries.md) for the general pattern.

## Project Structure

- [`App.tsx`](./src/App.tsx) contains the form, schema, URL-backed defaults, and explicit Conform prop mappings.
- [`form.tsx`](./src/components/form.tsx) contains only the compound-control adapters; shadcn Field composition stays in `App.tsx`.
- [`forms.ts`](./src/forms.ts) uses [`configureForms`](../../docs/api/react/future/configureForms.md#integrating-with-ui-libraries) to expose those mappings as typed field props.
- [`tests/index.test.ts`](./tests/index.test.ts) verifies validation, submission, focus, updated defaults, reset behavior, and repeated-value serialization.
